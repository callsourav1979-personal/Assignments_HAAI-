CV SORTING USING LARGE LANGUAGE MODELS
EXECUTION INSTRUCTIONS


1. PREREQUISITES

Python 3.10 or above is recommended.

The application can run on CPU or a CUDA-enabled GPU.
GPU execution is recommended for faster LLM inference.

Install the required environment dependencies using:

bash environment.txt

For Google Colab, run:

!bash environment.txt


2. PROJECT STRUCTURE

The project files should be placed in the same directory:

project_folder/
|
|-- main.py
|-- requirements.txt
|-- environment.txt
|-- execution.txt
|-- JD_*.pdf or JD_*.docx
|-- CV_*.pdf or CV_*.docx
|-- output CSV/JSON files


3. INPUT FILE NAMING CONVENTION

Job Description files must start with:

JD_

Examples:

JD_AI_Engineer.pdf
JD_SpecialEducator.docx


Candidate CV files must start with:

CV_

Examples:

CV_Candidate1.pdf
CV_Candidate2.docx


4. RUNNING THE APPLICATION

The application accepts three directory parameters:

python main.py <jd_folder> <cv_folder> <output_folder>

When all input and output files are maintained in the same project
directory, use "." for all three parameters:

python main.py . . .

For Google Colab, if main.py is located at the root directory:

!python /main.py . . .


5. PROCESSING WORKFLOW

The application performs the following steps:

1. Reads the Job Description and candidate CV files.
2. Extracts text from PDF and DOCX documents.
3. Loads LLM1 - Qwen2.5-1.5B-Instruct.
4. Converts the unstructured JD and CV content into structured JSON.
5. Performs skill and education matching.
6. Releases LLM1 resources to reduce memory usage.
7. Loads LLM2 - Qwen2.5-3B-Instruct.
8. Performs semantic evaluation of professional experience.
9. Calculates the overall candidate score.
10. Ranks the candidates.
11. Generates the final results in CSV and JSON formats.


6. OUTPUT

The application generates candidate ranking results in:

- CSV format
- JSON format

The results include candidate information, skill matching score,
experience matching score, education matching score, overall score,
recommendation and experience reasoning.


7. HARDWARE AND MEMORY MANAGEMENT

The application supports both CPU and CUDA-enabled GPU execution.

GPU execution is recommended for faster model inference.

The two LLMs are loaded sequentially rather than simultaneously
to reduce GPU memory consumption.

LLM1 is released from memory before LLM2 is loaded.


8. MODELS USED

LLM1:
Qwen/Qwen2.5-1.5B-Instruct

Role:
Structured information extraction from unstructured Job Description
and CV documents.

LLM2:
Qwen/Qwen2.5-3B-Instruct

Role:
Semantic evaluation of candidate professional experience against
the requirements of the Job Description.


9. NOTES

- At least one Job Description file starting with "JD_" must be
  present in the input directory.
- Candidate CV files must start with "CV_".
- Supported document formats are PDF and DOCX.
- The same directory can be supplied for JD, CV and output locations
  by using "." for all three parameters.
